## Anti-Patterns Verdict

**LLM 评估：** 首页没有明显 AI 痕迹。它遵循“Midnight IDE”概念：冷灰 + 单一蓝色强调、琥珀色仅用于深色模式标题、系统字体栈轻量。没有出现 Impeccable 绝对禁令（渐变文字、玻璃拟态、hero 指标、眉题、侧边色条等）。剩余的“查看更多 »”、标准列表按钮项目卡片、原始 SVG 社交图标都是平庸但忠实的博客主题惯例，属于“安全”而非“AI slop”。

## What's Working

1. **内容优先的清晰层级。** 作者区、最新文章、可选项目分区明确，`h2` 底边和 825px 行宽让阅读无压力。
2. **扎实的深色模式实现。** 同时支持 `prefers-color-scheme` 和手动 `data-user-color-scheme` 切换，琥珀色标题严格保留给深色模式。
3. **高度可配置的首页模块。** 作者名/头像、公告、社交图标、项目列表、章节标题、按钮文案均可在后台控制。

## Priority Issues

**[P1] “查看更多”硬编码 `/articles.html`**
- **Why it matters:** 如果 URL 重写关闭、归档 slug 变更或站点在子目录，首页主要 CTA 会直接 404。
- **Fix:** 用 Typecho 归档助手生成 URL，或暴露一个可配置的归档页选项；至少用 `$this->options->siteUrl` 推导相对路径。
- **建议命令：** `/impeccable harden index.php`

**[P1] 项目卡片存在两个指向同一 URL 的交互目标**
- **Why it matters:** 屏幕阅读器和键盘用户会连续经过两次相同目的地的焦点；路径冗余。
- **Fix:** 把整个卡片做成单一链接，或让图标/名称块非交互、只保留“访问”按钮。
- **建议命令：** `/impeccable harden index.php`

**[P2] 没有文章时缺少空状态**
- **Why it matters:** 若 `$this->next()` 无结果，“最新文章”标题和“查看更多”仍会渲染在空的 `.posts` 上方，页面显得损坏。
- **Fix:** 用 `<?php if ($this->have()): ?>` 包裹该区域，无文章时显示“暂无文章，稍后再来。”等友好提示。
- **建议命令：** `/impeccable onboard index.php`

**[P2] `viewport` 设置 `maximum-scale=1` 阻止移动端缩放**
- **Why it matters:** 违反 WCAG 1.4.4，低视力用户无法在首页双指放大到 200%。
- **Fix:** `header.php:8` 改为 `width=device-width, initial-scale=1`，移除 `maximum-scale=1`。
- **建议命令：** `/impeccable audit header.php`

**[P2] 文章 `<time>` 缺少 `datetime` 属性**
- **Why it matters:** 屏幕阅读器和搜索引擎无法可靠解析本地化日期字符串。
- **Fix:** 给 `<time>` 加 `datetime="<?php $this->date('c'); ?>"`。
- **建议命令：** `/impeccable harden index.php`

## Persona Red Flags

**Sam（依赖辅助技术）**
- 每个项目卡片有两次相同目的地的 tab 焦点。
- `<time>` 无 `datetime`，日期被当作普通文本播报。
- 若社交 SVG 未加 `aria-hidden="true"`，屏幕阅读器可能播报路径数据。
- “查看更多”里的 `&raquo;` 可能被读作“right-pointing double angle quotation mark”。
- 文章行和项目卡片的焦点指示依赖浏览器默认，CSS hover 背景不对应焦点状态。

**Casey（移动端分心用户）**
- `maximum-scale=1` 阻止 pinch-zoom。
- `.nav-links` 移动端水平滚动但无渐变、箭头或“更多”暗示，用户可能不知道还有页面。
- 作者头像和项目图标无 `loading="lazy"`。

**Riley（压力测试者）**
- 空文章列表会留下空洞区块且无解释。
- 硬编码 `/articles.html` 在归档页缺失或改名时 404。
- `icons_data` 格式错误（分隔符不对、SVG 未闭合）可能输出破损 HTML。
- `Notice` 支持原始 HTML，管理员账号被入侵时存在 XSS 风险。

## Minor Observations

- `h1.author-name` 在首页正确；需确认归档模板不会引入第二个 `h1`。
- 文件注释块里的版本检测脚本只在后台运行，但污染了源文件头部。
- `header.php:109` 无条件使用 `$` 绑定 PJAX 高亮处理器，关闭 `JqueryControl` 时会报 `ReferenceError`。
- `footer.php` 混用 MathJax v2 (`MathJax.Hub.Config`) 与 v3 (`MathJax.typeset`) API，可能破坏数学渲染。
- 深色模式按钮没有可见文本标签，不认识太阳/月亮图标的用户只能依赖 `aria-label`。
- 社交图标解析要求精确的 `" | "` 空格，输入错误容易产生畸形链接。
- 品牌链接用 `&nbsp;&nbsp;` 在 favicon 和标题间做间距，是轻微标记异味。
- 项目卡片移动端有 2px 底边，桌面端仅标题 hover 下划线，与文章行的桌面 hover 背景不一致。

## Questions to Consider

1. 页脚以主题署名结尾，声音大于作者本人。如果首页是自我介绍，最后一笔是否应该属于作者？
2. 文章行在桌面有 hover 背景，而项目卡片只有下划线。如果两者使用同一套交互语言会怎样？
3. “查看更多”链向独立归档页是否是最佳去向，还是内联“加载更多/更早文章”会更连续？
4. `Notice` 支持原始 HTML 带来灵活性，但也带来 XSS 风险。这份灵活性是否值得换成经过净化的 Markdown 字段？
5. 主题面向个人博客，但配置允许无限导航链接和社交图标。断点和溢出行为是否在配置极端情况下经过测试？
